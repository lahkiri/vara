# Computer Use في Vara — القدرة الأصلية

> v0.5.0 · **المرجع الكامل للتحليل:** `download/vara-computer-use-integration.md` (خارطة الدمج من تحليل الـ MCP)
> **المصدر:** MCP خاص بالمالك (38 أداة، Windows، Python) — نُقلت **فلسفته** إلى نواة Vara، لا أدواته فقط.

## القرار المعماري

القيمة الحقيقية للـ MCP ليست في الأدوات بل في **الانضباط البنيوي**: حلقة see→act→confirm إجبارية، focus-first، منع النقر الأعمى، بوابات هدم ثنائية، والاستجابة-كإرشاد. لذلك النقل تم على ثلاث طبقات:

```
النموذج (خيط الشات)          — يقترح فقط: [[sys]] computer_use {sequence}
        │ موافقة المالك (بطاقة)
        ▼
 vara-core::computer_use      — ActLoop: تحقق بنيوي + سُلّم صلاحيات + grounding + journal
        │ عقد ComputerUseAdapter
        ▼
 المحوّلات                    — Sidecar (MCP stdio، Phase 1) / Mock (اختبارات) / Rust-native (Phase 2)
```

## ما الذي يعمل فعلًا في هذا المستودع — بصراحة

**القدرة لا تعمل «من العلبة».** المُنفّذ الوحيد المضمون في هذا المستودع هو
`MockComputerUse` (سطح مكتب وهمي حتمي للاختبارات). الأيدي الحقيقية على ويندوز هي
**ملف تنفيذي خارجي (sidecar) غير مُضمَّن في هذا المستودع** — مجلد `sidecar/` يحتوي
`README.md` فقط (دليل التغليف)، ولا يوجد `server.py` ولا `vara-cu.exe` ولا أي
اعتماد Python هنا. لذلك:

- بدون تعيين `VARA_CU_SIDECAR` إلى أمر موجود فعلًا، يفشل التنفيذ **بصراحة**
  («sidecar not configured») ولا يدّعي نجاحًا.
- على Linux/macOS لا يوجد منفّذ أصلي بعد: القدرة تفشل بصدق، وكل منطق الانضباط
  يُختبر بلا رأس ضد الـ Mock.
- Phase 2 (نقل إلى Rust: `enigo` + `windows-rs` + DXGI + Windows.Media.Ocr) لم
  تُنفَّذ بعد؛ التفاصيل في `sidecar/README.md`.

## سُلّم الصلاحيات وأعلام السياسة (الأسماء الدقيقة)

| المستوى | الفئة | أمثلة | البوابة في الإعدادات |
|---|---|---|---|
| L0 | قراءة | screenshot, shot, verify, wait | `allow_screenshots` لكل SEE (و`wait` لا يحتاج) + `allow_computer_use` |
| L1 | إدخال قابل للتراجع | click, click_win, move, scroll, type, key(s), hotkey عادي, focus | `allow_computer_use` + بطاقة موافقة لكل تسلسل |
| L2 | دورة حياة/هدم | close_window, close_app, alt+f4, ctrl+w, ctrl+q, ctrl+f4, ctrl+shift+w | `computer_use_allow_close` + موافقة صريحة |

الافتراضات المشحونة: `allow_screenshots: false`، `allow_computer_use: false`،
`computer_use_allow_close: false`. النموذج **لا يقرأ الصورة نفسها**؛ اللقطة أثر
(artifact) للتحقق، وليست رؤية للنموذج.

تعيين الأعلام إلى `LoopPolicy` في النواة:

```rust
pub struct LoopPolicy {
    pub max_grant: GrantLevel,     // L1 افتراضيًا؛ L2 فقط مع computer_use_allow_close
    pub allow_screenshots: bool,   // autonomy.allow_screenshots — الافتراضي false
    pub final_evidence: bool,      // لقطة إثبات أخيرة عند نهاية غير مُتحقَّقة (true)
    pub correction_retries: u8,    // إعادة تصحيح واحدة كحد أقصى (1)
}
```

`LoopPolicy::default()` = `{ max_grant: L1, allow_screenshots: false,
final_evidence: true, correction_retries: 1 }` — أي أن الوضع الافتراضي يمنع
التقاط الشاشة ما لم يُمرَّر العلم صراحة.

## الضمانات التي يفرضها الـ ActLoop نفسه (لا نصائح للنموذج)

1. **اللقطة منحة، لا ميزة محوّل.** مع `allow_screenshots: false` يُرفض كل فعل SEE
   **قبل** استدعاء أي محوّل، ويُسجَّل في التقرير كـ«رفض سياسة» (عدّاد
   `see_denials`) لا كخطأ محوّل. وتُتخطّى أيضًا اللقطات الضمنية التي كانت الحلقة
   تلتقطها بنفسها: لقطة الإثبات الأخيرة، وإعادة الرؤية في التصحيح المحدود.
   و`ActLoop::check_policy` يرفض التسلسل كله قبل تشغيل أي شيء إذا احتوى SEE
   بلا هذه المنحة (فيتوقّف المسار قبل تشغيل الـ sidecar أصلًا).
2. **لا فعل بلا إثبات يُدَّعى.** الفعل المُعدِّل الذي لا تُثبته رؤية لاحقة يُحصى في
   `unverified_mutations` و`verify_discipline()` تهبط تحت 1.0، ويُكتب سبب صريح في
   `error` («screenshots are disabled … this run is NOT verified»)؛
   `LoopReport::fully_verified()` هي الإشارة الصادقة، لا `completed`.
3. **لا نقر أعمى — ولا نقر نافذة أعمى.** بوابة grounding تغطي **كل هدف بكسل**:
   `click` بإحداثيات، `click_win` (إحداثيات نسبية للنافذة)، `move`، و`scroll`
   بإحداثيات. الأفعال الموجَّهة بالاسم (`focus`, `type`، `hotkey`/`key`/`keys` مع
   نافذة، `close_*`) خارج البوابة عن قصد: لا يمكن أن تصيب عنصرًا خاطئًا.
   والـ Mock نفسه لم يعد يُؤسّس `click_win` من الفعل الذي يتحقق منه.
4. **الهدم جاف افتراضيًا — والحلقة هي التي تجفّفه.** عندما لا تمنح السياسة L2:
   - `close_window`/`close_app` مع `confirm: true` **تتحول داخل الحلقة** إلى
     `confirm: false` قبل أن تصل إلى أي محوّل (`CuOp::as_dry_run`)، ويُسجَّل الفعل
     كـ dry run. `confirm` القادم من النموذج طلب، وليس تصريحًا.
   - تركيبات الهدم (`alt+f4` وأخواتها) لا صيغة dry run لها: الحلقة **لا ترسلها
     إطلاقًا** وتكتب الإيصال بنفسها. المحوّل لا يُطلب منه أبدًا إغلاق شيء حقيقي
     تحت L2، ولا يُمكن لمحوّل أن يدّعي نجاحًا بعد تجفيف (يُحوَّل إلى dry run فاشل).

   حدّ صادق: ما تضمنه الحلقة هو **ما ترسله** (لا `confirm: true` تحت L2، ولا
   تركيبة هدم إطلاقًا). لو تجاهل محوّلٌ معطوب `confirm=false` وأغلق فعلًا، فلا
   تستطيع الحلقة التراجع عن الفعل — لكنها تسجّله كفشل dry run مع سبب صريح، ولا
   تُحصيه أبدًا كفعل مُنفَّذ أو مُتحقَّق منه.
5. **تصنيف التركيبات لا يُخترق بالكتابة.** `normalize_combo` يقسّم على `+`،
   ويشذّب، ويصغّر الأحرف، ويطوي الأسماء البديلة (`control`→`ctrl`,
   `option`→`alt`, `cmd`/`command`/`super`/`win`/`windows`/`meta`→`win`)، ويرتّب
   المعرّفات بترتيب ثابت — لذلك `"Control + W"` و`"ctrl+W"` و`"CTRL + w"` و
   `"w+ctrl"` و`"Alt + F4"` كلها L2، بينما `ctrl+s` يبقى L1.
6. **التأكيد بنيوي**: تسلسل ينتهي بفعل غير مُتحقق منه يحصل على لقطة إثبات أخيرة —
   إذا (وفقط إذا) كانت اللقطات ممنوحة.
7. **تصحيح محدود**: إعادة واحدة فقط، وفقط إذا فشل قبل أي فعل مُعدِّل.

## عالم الاختبار (MockComputerUse)

شاشة ويندوز افتراضية حتمية تحاكي فشل الواقع: إطارات ستاتية من اللوحات المتحركة
(انضباط settle)، سرقة تركيز (تشخيص `active`)، رفض النقر الأعمى (بما فيه النقر
النسبي)، وtyping بلا تركيز يفشل بإرشاد. **15 سيناريو** في
`crates/vara-core/tests/computer_use_harness.rs`:

| # | ما يقفله |
|---|---|
| s1–s8 | التدفق المؤسَّس، الإطار الستاتيكي، بوابة الهدم، النقر الأعمى، سرقة التركيز، التصحيح المحدود، رفض المخطط، اكتمال السجل |
| s9 | تصنيف سُلّم الصلاحيات |
| s10 | رفض L2 في نقطة الدخول قبل لمس المحوّل |
| s11 | لقطة الإثبات البنيوية عند نهاية غير مُتحقَّقة |
| s12 | `allow_screenshots: false`: رفض SEE قبل المحوّل + تخطّي الالتقاط الضمني + إبلاغ الطفرات غير المُتحقَّقة |
| s13 | رفض `click_win` الأعمى، وبقاء الأفعال الموجَّهة بالاسم خارج البوابة |
| s14 | تجفيف الهدم داخل الحلقة: المحوّل لا يُطلب منه أبدًا إغلاق حقيقي تحت L2 (مع شاهد يُثبت أنه يُغلق فعلًا عند منح L2) |
| s15 | كل صيغ التركيبة المهلكة تُصنَّف L2 ولا تُرسل إلى أي محوّل تحت L2 |

## جانب الأبحاث

`scripts/vara_harness_v2.mjs` — منفّذ حملة الأذرع الأربعة المسجّلة مسبقًا
(EXPERIMENT_DESIGN.md): 24 تشغيلة بميزانية 90k token صارمة، نموذج مسمى في كل صف،
أدوات بحث/fetch حقيقية، وسجل سبب التوقف. مع `check_provenance.mjs` كبوابة M1
مستقلة. (وجه الكيان: السيناريوهات أعلاه تقيس `verify_discipline` و
`grounded_clean` وحدود التصحيح — ولاحقًا ستقيّم تخطيط الكيان نفسه بمقاييس
الانضباط نفسها.)

## Phase 2 (مخطط)

نقل كامل إلى Rust: `enigo` (إدخال) + `windows-rs` (نوافذ) + DXGI (لقطة) +
**Windows.Media.Ocr** (OCR بلا Tesseract) + UIA لاحقًا — كلها خلف نفس عقد
`ComputerUseAdapter` فلا يتغير شيء فوقه، بما في ذلك البوابات أعلاه. التفاصيل
وخطوات تغليف الـ sidecar الحالي في `sidecar/README.md`.
